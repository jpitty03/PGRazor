# v0.3.6.2

Revision of the v0.3.6.1 fork build. Adds the focused follow-up fixes plus a dedicated berry fallback setting.

## Settings import/export

- Fixed backups failing to import: the tag-rule keys were in the allowlist without validators. Numeric keys (`smartCatchRareMask`, `smartCatchRareIvMin`) and berry/tag/species keys now have per-key validation matching persistence, so default and custom exports import again.
- Added a full default/custom export→import round-trip test, including empty, multiple and Unicode tag names and invalid values.

## Catch berries

- When a rule berry is out of stock, the native controller no longer fills all three transport slots with unavailable berries and submits nothing. Stocked candidates are resolved before the list is limited, so the overlay and the berry actually fed agree.
- New **Fallback berries** setting in the VGP+ tag-rule section: pick up to three berries in order. They are used only when the configured rare/candy berry is unavailable; if they are also unavailable, the map's berry-priority list is used.
- Silver Pinap is now saved as item 707 (matching the game and berry picker); old saves using 708 are migrated.
- Added regression tests for exhausted rules, partial stock, duplicates, empty lists and the new fallback order.

## VGP+ tag rules

- Refreshing storage-tag membership now bumps the effective-rule revision, so Pokémon skipped under the old membership are considered again. Unchanged refreshes no longer clear the cache repeatedly.
- While tags are still loading, the controller defers the decision instead of caching a definitive rejection.
- Added a native regression test for membership changes, warmup deferral and unchanged refreshes.

## Build

- Based on PGRazor v0.3.6 with the fork's v0.3.6.1 changes, plus the Rocket counter cards from the current source branch.
- Device-free checks: 192 tests; only the four pre-existing `test_native_prerequisites.py` environment failures remain. Android and native builds both pass.
