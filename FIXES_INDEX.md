## Issue Overview

### P1 — SettingsBackupRules.java Validation Failures (Critical)
**Problem:** New tag-rule keys (`smartCatchRareMask`, `smartCatchRareIvMin`, etc.) lack dedicated validators. They fall through to a generic integer parser that misinterprets berry IDs and rejects valid values with max=7.

**Impact:** Settings backups fail to import, breaking configuration persistence for users who upgraded from earlier versions.

### P2a — Berry Rule Fallback Discards User Stock (High)
**Problem:** `with_rule_berry()` fills a 3-slot array with rule berries before appending user priorities without considering inventory stock. If all three rule berries are out but the user has available ones, those fallbacks are omitted while the UI still displays them.

**Impact:** Native controller submits without feeding berries, creating a mismatch between what the overlay shows and what actually happens during encounters.

### P2b — Tag Membership Cache Stale After Refresh (Medium)
**Problem:** `read_tags()` updates membership vectors but doesn't increment the revision counter. Only serialized config changes increment it, so VGP controller skips clearing old exclusion decisions when tag membership changes in-game without changing PGRazor settings.

**Impact:** Skipped spawns remain excluded for an hour even after their family is added to a storage tag, causing missed catches and inconsistent behavior.
